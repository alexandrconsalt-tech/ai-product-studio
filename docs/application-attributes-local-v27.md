## Контракт и правила записи

Extractors возвращают `status`: `determined`, `explicitly_declined`, `not_determined`.

Для Interest/Funding/Purchase отсутствующее значение равно `null`. Для даты отсутствует `next_contact_at`; `detected=false`. Категориальные значения Funding/Purchase остались в исходном нижнем регистре RTF. Текст «не определено» является подписью состояния, а не сохранённым значением.

Interest дополнительно возвращает `declined_values` и `decline_evidence`: явный отказ от ипотеки не уничтожает подтверждённый интерес к строительству. При общем отказе отвечать список отдельных направлений может быть пустым. Если подтверждённых интересов нет и есть отказ, status=explicitly_declined.

Judge принимает четыре независимых подготовленных входа и возвращает по каждому `{verdict,status,reason}`. Вердикты: `accepted`, `rejected`, `not_determined`, `technical_error`. Он не возвращает новое значение. Статус, не совпадающий со статусом Extractor, или постороннее поле в вердикте считаются технической ошибкой только этого атрибута.

В итоговых объектах:

- `attributes` — значения;
- `attribute_states` — предметные состояния из трёх перечисленных выше;
- `update_actions` — SET, SET_DECLINED, SKIP, ERROR, KEEP_FALLBACK;
- `sources` — ai, none, fallback;
- `technical_errors` / `blocked_attributes` — отдельная диагностика.

`attribute_statuses` внутри проверенного Judge сохраняет техническую готовность (`ready` / `technical_error`); её нельзя смешивать с `attribute_states`.

Gate и CRM работают кодом, не вызывают LLM, имеют строгие JSON schemas и нулевые токены/стоимость. При rejected результат не записывается. Исторические отчёты не переписываются.

## Время и fallback

- `communication_created_at` — время создания аудио/коммуникации, не гарантированное время разговора.
- Допустимы явные метки `audio_created_at`, `communication.created_at`, `audio.created_at`, которые приводятся к этому полю. `call_datetime`, `call_end_datetime`, `started_at` и duration не используются.
- По умолчанию timezone=Europe/Moscow. В UI можно выбрать другую зону; дата в UTC отображается в выбранной зоне.
- Для ручного текста нужно самостоятельно указать время создания коммуникации. Старое поле времени звонка не переименовывается молча и не переносится в новое поле. Текущее время автоматически не подставляется.
- Относительные даты рассчитываются от creation time. Дата с указанными годом и временем рассчитывается и без опорной метки. Неизвестная формулировка или невалидная дата не сохраняется; остальные атрибуты продолжают работать.
- Сохранены существующие соглашения normalizer: дата без часа → 10:00, вечер → 18:00, диапазон 30–40 минут → середина 35 минут. `precision` сохраняется; UI называет такую дату расчётным ориентиром, а не точным временем договорённости.
- В локальной Studio нет серверного планировщика fallback +24 часа. При отсутствии подтверждённой AI-даты сохраняется SKIP и `PRESERVE_SYSTEM_FALLBACK_24H`; серверный механизм не подменяется новым таймером.
- Если backend передал уже вычисленное `next_contact_fallback_at`, оно проходит как source=fallback, action=KEEP_FALLBACK, status=not_determined, без подтверждения через transcript. Дата не пересчитывается.
- Подтверждённый отказ от дальнейшего контакта → SET_DECLINED и NO_CONTACT. Fallback не превращает такой отказ в новую договорённость.

## Настройки и миграция

Первая загрузка версии v27 обновляет промпты и response contracts всех семи этапов. Модели, провайдеры, бюджеты токенов и история сохраняются. Полный старый конфиг до миграции сохраняется в Local Storage под ключом `pipelineLabV3.pipelineConfig.<projectId>.before-v27`; дополнительная существующая резервная копия `.previous` тоже сохраняется. Правки промптов после перехода на v27 переживают reload и запуск.

Старые вложения RTF остаются историческими источниками, новый исполняемый вариант находится в `public/ai-application-attributes-pipeline-v27.js`.

## Что проверить в AI Product Studio

Обновить страницу «AI Атрибуты в Заявке». Для примеров ниже указать создание коммуникации `27.09.2026 10:00:00`, Europe/Moscow. Проверять на обычном выбранном AI-провайдере; затем скачать JSON-отчёт.

| Сценарий | Ожидаемый результат |
|---|---|
| «Интересуют новостройки, нужна ипотечная консультация» | Два интереса, status=determined |
| «Хотим построить дом, ипотека не нужна» | Строительство; Ипотека отдельно в declined_values |
| Только «нужна юридическая проверка сделки» | AI не выдаёт удалённые из справочника направления |
| «Не хочу обсуждать, откуда деньги» | Источник средств: явный отказ, null + explicitly_declined |
| Источник средств не обсуждался | not_determined, SKIP; отличается от отказа |
| «Не знаю, когда купим» | Срок не определён, это не отказ |
| Агент: «Перезвоню завтра в 15:00», клиент подтверждает | 28.09.2026 15:00, source=ai, проходит все четыре этапа |
| Агент: «Напишу через час» | 27.09.2026 11:00; опора — создание коммуникации |
| Только «показ завтра в 15:00» | Не формировать отдельный следующий звонок |
| «Больше не звоните и не пишите» | Явный отказ от контакта, NO_CONTACT |
| Нет договорённости о контакте | Не придумывать AI-дату, сохранить существующий серверный fallback |
| Очистить время создания; есть «завтра в 15:00» и подтверждённый источник средств | Дата не рассчитывается, источник средств остаётся доступным |
| Повторить запуск с другим текстом | Нет переноса атрибутов из предыдущего разговора |

В отчёте проверить `attribute_states`, `sources`, `update_actions`, `__communication_metadata_audit`, `temporal_normalization_audit` и версии schemas `*_v2`. На Gate и CRM — actual_model=code, tokens=0.
