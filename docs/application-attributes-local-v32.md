# Строгий алгоритм четырёх атрибутов — локальная версия 32

Область изменений: только «AI Атрибуты в Заявке» в AI Product Studio. Основание — последнее требование владельца: строго четыре атрибута, значения по справочнику, только подтверждённые разговором данные. Синхронизированные исходные материалы и RTF не изменялись. GitHub, commit, push, deploy и запись в боевую CRM не выполнялись.

## Что исправлено

- Вместо накопленных инструкций прежних версий действуют единые актуальные промпты пяти LLM-этапов. Сохранённые пользовательские шаблоны и настройки моделей остаются доступными; обязательная политика добавляется при миграции и проверяется при формировании запроса. До миграции сохраняется резервная копия настроек.
- Уточнено правило однозначного контекста новостройки: запрос клиента на конкретный объект/просмотр и описание агентом именно этого объекта как строящегося оцениваются вместе. Клиент не обязан повторять слово «новостройка». Это не распространяется на другой дом рядом или исторический ДДУ продавца.
- В `attributes` остаются ровно четыре поля. Интерес — массив из шести допустимых направлений; источник средств и срок покупки — одиночные значения из согласованных списков. Синонимы, сокращения, новые категории и свободные пояснения не допускаются схемой.
- «Не определено» отображает отсутствие достоверного значения: `not_determined`, `null`, `SKIP`. Существующее значение заявки не перезаписывается. Прямой отказ остаётся отдельным состоянием с подтверждающей цитатой.
- Стандартные Extractor больше не генерируют свободные пояснения вместо источника средств или срока покупки: совместимое поле `context` возвращается как `null`. Старые диагностические данные читаются, но не становятся значениями атрибутов.
- Убрана запись придуманных часов: 10:00 для дня, 18:00 для вечера, середины диапазона 30–40 минут. День без часа, период дня, диапазон, открытая граница «после 20 августа», приблизительное время или час без однозначного дня не создают точную AI-дату.
- Точное время относительно события сохраняется: после переноса показа на 15:00 обещанный звонок за час соответствует 14:00. Код проверяет точность независимо от Judge; `accepted` само по себе не разрешает сохранить произвольный час. Дата не записывается, если она уже прошла относительно переданной временной опоры.
- Основная карточка содержит ровно четыре атрибута. Сведения о показе и метрики перенесены в раскрываемые детали. Это не дополнительные поля заявки.

## Алгоритм записи

1. Каждый Extractor получает текущую транскрипцию один раз и возвращает кандидат, состояние и подтверждение.
2. Attributes Judge независимо проверяет четыре кандидата: смысл, цитату, отрицания, контекст текущей покупки, исправления и допустимость значения. Judge не переписывает значение.
3. Детерминированный Quality Gate разрешает только подтверждённые значения справочника. Ошибка или отклонение одного атрибута не блокирует остальные.
4. Детерминированный CRM result формирует `SET` только для разрешённого значения, `SKIP` при отсутствии данных, отдельное действие для подтверждённого отказа. Для следующего контакта требуется точная рассчитанная дата и время.
5. Если AI-дату рассчитать нельзя, существующий механизм +24 часа сохраняется. Уже переданная серверная дата получает `KEEP_FALLBACK` и источник `fallback`. Без переданной серверной даты Studio возвращает политику `PRESERVE_SYSTEM_FALLBACK_24H`, не создавая второй таймер. Прямой подтверждённый отказ от контактов сохраняет `NO_CONTACT`.

## Справочники и неоднозначности

- Интерес: Новостройки; Ипотека; Инвестиции в регионах; Безопасность сделок; Юридическое сопровождение; Строительство. Можно несколько значений.
- Источник: наличные / депозит; ипотека одобрена; ипотека в процессе; продажа своей квартиры. Если ни одно значение не подтверждено — не определено, без обновления.
- Срок: до 1 месяца; 2–3 месяца; 3–6 месяцев; более 6 месяцев. Если ни одно значение не подтверждено — не определено, без обновления.
- Для общей границы трёх месяцев применяется категория «2–3 месяца»; «3–6 месяцев» — свыше трёх до шести включительно. Интервал между одним и двумя месяцами не имеет отдельной категории в данном справочнике: значение не округляется и не заполняется. Неоднозначный диапазон через несколько категорий также не заполняется.
- Смешанное финансирование не разрешает произвольно выбрать один источник. Он заполняется, только если основная модель однозначно следует из разговора.
- Обсуждение возможности семейной ипотеки не подтверждает начавшееся оформление; дедлайн банковского одобрения не равен сроку покупки.

## Время коммуникации

Вход `communication_created_at` обозначает время создания аудио/коммуникации, а не фактическое время звонка. Используется выбранный часовой пояс, по умолчанию Europe/Moscow. Текущая дата не подставляется автоматически. Без календарной опоры относительная договорённость сохраняется для просмотра, а абсолютная AI-дата остаётся пустой. Абсолютная дата с годом и временем может быть рассчитана без этой опоры.

## Сценарии проверки в UI

1. Версия 32; четыре основных поля. Интересы можно выбрать одновременно, дополнительных категорий нет.
2. «Банк одобрил ипотеку» → ипотека одобрена; «заявку подали, ждём решения» → ипотека в процессе; «реально ли получить ипотеку?» не подтверждает начало оформления.
3. «Покупаем через два месяца» → 2–3 месяца; «банк должен одобрить до конца недели» не подтверждает срок покупки.
4. «Перезвоню завтра в 15:00» с известной датой создания → точная дата; «созвонимся завтра», «в пятницу», «вечером», «через 30–40 минут», «после 20 августа» без точного времени → существующий механизм +24 часа.
5. «Больше не звоните» → подтверждённый отказ, без назначения нового контакта. Отсутствие информации по одному полю не очищает его и не блокирует остальные.

## Результаты проверки

- Полный набор unit-тестов: 1006 passed, 1 существующий skipped. Профильных проверок — 73.
- Линтер и production-сборка прошли. Сборка выполнена в изолированной копии актуальных исходников, чтобы не менять работающий localhost:3000.
- Визуально проверены основная карточка и раскрываемые детали на desktop и mobile: четыре поля, без наложений и горизонтального переполнения.
- Реальный запуск через выбранный AI Tunnel / gpt-5-mini завершил все семь этапов. В результате: интерес — Новостройки и Ипотека; источник средств и срок покупки — not_determined; context обоих полей — null; звонок завтра в 14:00 относительно последнего согласованного показа в 15:00. Без даты создания записи календарная дата контакта остаётся null, политика +24 часа сохранена. Технических ошибок и заблокированных атрибутов в итоговом результате нет.
- Автоматические браузерные тесты используют контролируемые ответы модели и проверяют передачу данных, контракты, отказ, изоляцию ошибок, экспорт, временные расчёты и UI. Это не измерение общей смысловой точности модели; присланный разговор дополнительно проверен с реальной моделью.
- Итоговый полный браузерный прогон: 226 passed, включая 88 профильных сценариев на desktop/mobile. Ошибок страницы и console в проверяемом UI-сценарии нет.
