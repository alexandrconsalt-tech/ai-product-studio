## Реализованная бизнес-логика

- Fact Agent получает `business_priority` и отбрасывает служебный/карточный шум.
- Needs формирует `required/preferred`, сохраняет provenance и каноническое финансирование.
- Store применяет deterministic Need Recovery только при пустом ответе Needs и прямом evidence клиента.
- Summary планируется из канонических полей Store, ограничивает приоритетные требования, удаляет повторы, JSON-residue и незавершённые цитаты, сохраняет блок «Потребности клиента».
- Completeness проверяет только реально существующие closed expected items.
- Usefulness не штрафует за данные карточки CRM и за отсутствие срока, если клиент прямо подтвердил отсутствие срока.
- Action Judge не требует deadline/channel, которых нет в `primary_next_step`.
- Format детерминированно синхронизирует найденные проблемы с `issues`.
- Перед CRM сохраняются `summary_diagnostics`; это диагностика, а не искусственное повышение score.
